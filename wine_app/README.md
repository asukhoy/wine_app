# 🍷 Отбор хороших вин — демо на Streamlit

Приложение к ДЗ-3 (ML, НИУ ВШЭ, 2026). Логистическая регрессия (`StandardScaler + LogisticRegression`) по результатам лабораторного анализа предсказывает, хорошее ли вино (экспертная оценка ≥ 7). Модель обучена в ноутбуке `HW3_MMDA.ipynb` и внутри приложения **не обучается**.

## Содержимое

| файл | что это |
|---|---|
| `app.py` | приложение |
| `model.joblib` | обученный пайплайн (скейлер + логистическая регрессия) |
| `config.json` | порог по умолчанию (подобран на валидации по максимуму F1) |
| `test.csv` | тестовая выборка с `target` (для вкладки с метриками) |
| `requirements.txt` | версии библиотек |

## Запуск локально

Нужен **Python 3.13** (проверено на 3.13; подойдёт и 3.11–3.12, если для них ставятся версии из `requirements.txt`).

```bash
cd wine_app
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Приложение откроется на http://localhost:8501.

## Вкладки

1. **Оценка одного вина** – ввод 12 признаков (диапазоны – min/max по тесту, по умолчанию – медианы), вероятность и решение при текущем пороге.
2. **Модельные метрики** – матрица ошибок, precision / recall / F1, ROC- и PR-кривые с отмеченной точкой текущего порога, подсказка для сомелье.
3. **Пакетное предсказание** – загрузка CSV без `target`, таблица с вероятностями и решениями, скачивание результата. Если в файле не хватает столбцов, выводится понятная ошибка.
4. **Что выучила модель** – коэффициенты логистической регрессии.

Порог задаётся в боковой панели и общий для всех вкладок (`st.session_state`).

## Кэширование (задание 4.5)

- Модель загружается функцией с `@st.cache_resource`, тестовая таблица – с `@st.cache_data`, вероятности на тесте считаются один раз в `@st.cache_data`-функции `test_proba(_model, X)`. При движении слайдера пересчитывается только сравнение с порогом.
- **Почему `cache_resource` для модели, а `cache_data` для таблиц?** `cache_resource` хранит **один общий объект** на весь сервер и отдаёт его всем сессиям по ссылке, без копирования и сериализации. Это нужно для «ресурсов» вроде модели или подключения к БД: они тяжёлые, неизменяемые и не должны копироваться. `cache_data` сериализует результат и при каждом вызове отдаёт **свежую копию**. Это нужно для данных (DataFrame, массивы): изменение возвращённой таблицы в коде не испортит кэш. Ключ кэша – хеш аргументов; модель Streamlit хешировать не умеет, поэтому она передаётся как `_model`.
- **Что будет без декоратора?** Streamlit перезапускает скрипт сверху вниз при каждом действии пользователя, и `joblib.load` читал бы и десериализовал модель с диска на **каждый** сдвиг слайдера, а следом заново считал бы `predict_proba` на всём тесте. Приложение тормозило бы, а при нескольких пользователях в памяти копились бы лишние копии модели.
